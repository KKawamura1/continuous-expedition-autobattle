# 坑の前線（連続進軍オートバトル試作）

スマートフォンの縦画面で、自律して戦う調査隊を観察し、好きなときに一時停止して改造するゲームの試作です。購入した部品が戦場でどう噛み合い、前線をどこまで押し上げるかを試します。

## 起動

Node.js 20.19以降または22.12以降を用意します。

```sh
npm install
npm run dev
```

表示されたURLをブラウザで開きます。iPhoneで試す場合は、同じネットワーク上のPCで起動し、表示されたNetwork URLを開けます。`npm test`で戦闘と拠点のルールを、`npm run build`で配布用ビルドを確認できます。

## Cloudflare Workers

mainの本番環境: [https://continuous-expedition-autobattle.focusgate-kkawamura.workers.dev](https://continuous-expedition-autobattle.focusgate-kkawamura.workers.dev/)

Cloudflare WorkersのGit連携でこのGitHubリポジトリを接続すると、Production branch（`main`）への更新で本番公開され、Preview buildsを有効にすると他のブランチやプルリクエストにプレビューURLが作られます。プレビューURLはプルリクエストにも投稿されます。

設定値は次の通りです。

- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`
- Preview command: `npx wrangler preview`
- Root directory: `/`

`wrangler.jsonc`ではViteの出力先`dist`をWorkers Static Assetsとして配信し、Workers Preview URLを有効にしています。`npm run build`はTypeScriptの型検査を通してからViteで公開ファイルを作ります。Cloudflareがビルドとデプロイを行うため、GitHub Actionsは使いません。

## 遊び方

1. 「進軍を始める」で自律戦闘を始めます。坑道を進む5人が前方の敵群と遭遇します。
2. 距離、進軍速度、敵の滞留、撃破圧、被害、収入を観察します。
3. 「改造・一時停止」で時間を止めます。敵を倒して得た遠征資金を、戦い方を変える部品や性能の調整に使えます。
4. 再開して変化を観察します。300mごとの中継拠点では自動停止し、全額を再配分できます。
5. 危険域でも自動停止します。資金で改造した後に「進軍を再開」を押して続行するか、最後の拠点へ撤退できます。ページを閉じても、その地点から停止状態で再開できます。

再生速度は1×、2×、4×に切り替えられます。別のタブへ移ると戦闘は停止します。

## 戦線・移動と復帰

敵と味方はワールド座標で移動します。敵は認識距離内の最寄りの生存隊員を2次元で追い、近接隊員は接近、遠距離隊員は適正距離を保ちます。被害・密集・侵入・負傷・戦闘不能は部隊共通の後退判断に作用し、仲間から離れすぎた隊員には集団へ戻る力が働きます。

戦線は最前線の生存隊員と最も後方の生存敵のうち、後方の位置です。そのワールド位置を距離に換算し、変位を時間で割った実測値を進軍速度として表示します。カメラは戦線を滑らかに追従します。前線の前方16mには空間密度に応じた敵が存在し、敵味方の相対移動で遭遇する分だけ実体化します。通常の後退では画面外の敵も保持され、再接触できます。

生存者は毎秒0.45HPを自動回復し、ツグミは攻撃時に追加で治療します。HPが0になった隊員は9.5秒間戦闘不能となり、最大HPの45%で部隊の後方へ復帰します。初回の危険停止と全滅時の戦線崩壊・拠点への撤退を維持しています。敵の攻撃とナギの庇護は実際の距離で判定します。拠点到達ではその場で回復し、敵配置を保持します。拠点への撤退は保存した資金・改造へ戻す遠征の再開始です。

## 今回の実装範囲

5人の調査隊、4種類の敵、13種類の改造、空間密度による敵遭遇と深度に応じた強化、前線の進軍・後退、拠点での保存と再配分を一つの画面に収めています。坑、記録、5人の人物は以前の案から着想を得た仮の表現です。具体的な物語や技能体系は、戦闘の手応えを見て育てる予定です。

敵と味方は位置を持ちます。射撃による引き寄せ、衝撃による押し出し、接触による損傷、周囲への薙ぎ払い、近くの敵へ跳ぶ鎖雷などは、この位置や重量を共有します。共通の戦場を介して、組み合わせが生まれます。

進軍速度は戦線の移動から求め、被害や敵の密集は隊員の移動判断に作用します。数値と改造候補は検証用です。[試作の実装判断](docs/prototype-notes.md) に詳しく記しました。

## コードの構成

- `src/main.ts` は画面、入力、ゲームループをつなぎます。
- `src/canvas.ts` はCanvas上の戦場描画を担当します。
- `src/simulation.ts` はゲーム進行と戦闘ルールを担当します。
- `src/content.ts` は調査隊、敵、改造候補の定義をまとめます。
- `src/save.ts` はセーブの読込・検証・書出しを担当します。描画効果と直前の比較表示は保存せず、v1〜v4の既存形式を読み込み、遭遇積算値を含むversion 5形式で保存します。
- `src/types.ts` はこれらの共有型、`tests/` はブラウザに依存しないシミュレーションとセーブのテストです。
