# 連続進軍オートバトル：企画・実装ブリーフ

この文書は、実装時に守りたい**体験と判断基準**をまとめたものです。完成仕様書ではありません。「必須」は試作で体験として成立させたいこと、「有力仮説」は最初に試す作り方、「未決定」は検証後に選ぶことを指します。例示した数値やスキル名を、そのまま仕様として扱わないでください。

## 作りたい体験

> 自分で組んだ戦闘機械が自律して戦う。その限界を観察し、部品を買って改造し、予想と違う働きも含めて理解しながら、前線をさらに押し上げる。

局所的な強化効果は購入前に理解できる。一方、戦場全体でどれだけ効くかは実際に動かして初めて分かる。**観察 → 仮説 → 改造 → 再開 → 理解**の循環が面白さの中心です。プレイヤーが考えたいときに止められ、普段は判断を求められず進みます。現実時間の速さで競わせません。

## 必須：試作で成立させる体験

| 項目 | 守りたいこと |
| --- | --- |
| 自律した連続戦闘 | スマートフォンの縦画面を前提に、敵が流入し、味方が自動で戦い続ける。毎ターンの指示を要求しない。 |
| 任意の一時停止 | プレイヤーが好きなときに止め、稼いだ資源でビルドを変え、再開できる。一時停止を頻繁に押すほど有利な瞬間コマンド操作にはしない。 |
| 動く前線 | 押せば距離が進み、拮抗すれば止まり、処理しきれなければ後退する。強化の手応えと限界を距離・進軍速度・戦場の様子から読める。 |
| 観察に根拠のある購入 | 何が詰まっているか、何を変えたか、その結果がどう変わったかを画面から追える。単なる資金待ちにしない。 |
| ビルドによる異なる振る舞い | 強さの数値差だけでなく、敵の集まり方、被害の受け方、押し返すタイミングなどが変わる。敵には相性差があってよいが、特定の戦法だけを実質必須にしない。 |
| 共通ルールから生じる相互作用 | 個別スキル間の専用コンボを大量に定義するより、複数の部品が同じ戦場の性質を参照して自然に噛み合う。初見でも因果を説明できる範囲の複雑さを目指す。 |
| 遠征の継続 | 戦場と距離が一本の道としてつながり、到達した拠点が保存・再開・構成の見直しの区切りになる。離席だけで気付かないうちに進行を大きく失う体験を避ける。 |

## 有力仮説：最初に試す作り方

これらは体験を実現するための候補です。試作で狙いに合わなければ変更します。

### 戦場と報酬

- 敵は画面上側から現れ、パーティは下側から進む。戦闘を区切るクリア画面を挟まず、距離に応じて敵の種類や圧力、背景が変わる。
- 撃破が前進に寄与し、被害や基礎的な抵抗が押し戻す。**進軍速度 ≈ 撃破圧力 − 基礎抵抗 − 被害圧力**は挙動を考えるための仮式であり、計算式の指定ではない。敵の流入は処理負荷として働く。強化直後の前進がすぐに敵圧で相殺されないよう、追従の仕方を調整する。
- 敵を倒して資金を得て、奥の敵ほど報酬を高くする。速度そのものへの追加ボーナスは初期試作では不要そうだが、報酬と前線の釣り合いで判断する。
- 後退中にも戦闘と購入による立て直しができる。危険域では自動で止める案がある。自発的な撤退、敗走、途中セーブの詳しい扱いは後述の未決定事項とする。

### 改造の二つの時間尺度

- **構造を決める選択**：たとえば「遠距離攻撃で敵を引き寄せる」のように、戦場に新しい因果を加える。拠点で構成を大きく組み直す。
- **遠征中の調整**：たとえば引く強さや射程を変えるように、今見えている問題へ資金を使う。

この二層化は後のメモで強まった有力案です。スキル体系、通貨、画面、保存規則まで二つに固定する意味ではありません。先のメモには、一つの遠征資金で大小の部品を買い、拠点で全再配分する案もあります。まず必要なのは、**構造を試す選択と、戦場を見て行う調整の両方に意味があること**です。

### 共有する戦場の性質

距離、位置、速度、重量、密度、接触、押し引き、貫通などは、直感的な共通ルールの候補です。物理・魔法も、極端な耐性で必須解を作るためではなく、戦場での振る舞いを変える手段になり得ます。たとえば「引き寄せで敵が密集し、範囲攻撃が効く」「押し出した敵が別の敵に衝突する」といった関係を試します。すべての物理量や例示スキルを初期実装する必要はありません。

## 最初の試作で確かめること

一画面、短い一区間、一つの拠点、少数の敵と、異なる挙動が見える複数のビルドから始めます。数や距離は試作の都合で決めます。自律戦闘、一時停止中の購入、進軍・膠着・後退、拠点での保存と再構成までを一巡させます。恒久成長、物語、多数の地域やスキルは、この循環の評価に必要になってから検討します。

試作では、次の問いを実プレイで確認します。

1. プレイヤーは戦場で問題を発見し、自発的に止めて改造し、すぐ結果を見たくなるか。
2. 押す・止まる・後退する理由と、購入が効いた理由を説明できるか。距離や速度に加え、敵の滞留、被害、資金の入り方など必要な手掛かりが見えるか。
3. 異なるビルドで戦場の挙動と次に買いたいものが変わるか。単なるDPS比較や専用コンボ探しに収束しないか。
4. 強化後の前進が気持ちよく、劣勢でもただ待つ時間にならないか。後退中の稼ぎが安全地帯での放置を最適にしないか。
5. 拠点での再構成と、途中での購入・撤退・再開が、試行を促しつつ離席への不安を生まないか。

## 未決定：実装しながら検証して選ぶこと

| 論点 | 判断の基準 |
| --- | --- |
| 技能の供給 | 固定ツリー、ショップ、ランダム候補をどこに使うか。観察から購入理由が生まれ、繰り返しても同じ最適順に固定されないか。画面上の少数候補表示と、実際の選択制限は区別する。 |
| 成長・通貨・リセット | 二層の選択を別資源にするか、遠征資金に統合するか。拠点間の購入は取り消せるか、拠点で何を振り直せるか、長期の解禁をどう扱うか。 |
| 前線と敵圧 | 進軍速度、敵出現と追従、後退時の敵、表示値の平滑化をどう結ぶか。数式よりも理解可能で安定した挙動を優先する。 |
| 拠点・敗走・中断 | 拠点の間隔、保存対象、途中再開、危険域での自動停止、撤退時に失うものをどう定めるか。気軽な実験と到達の重みを両立する。 |
| 操作と情報量 | 倍速の有無、一時停止画面、購入候補の見せ方、観察用の表示をどうまとめるか。縦画面で読めて、待ち時間や操作負担を増やさないか。 |
| 世界の広がり | 地域の変化、恒久的な解禁、物語上の終点をいつ導入するか。初期試作の成功条件には含めない。 |

## 実装時の判断

技術構成や内部アーキテクチャはこの文書では指定しません。候補が複数ある場合、まず小さく動かし、上の問いに答えられる実装を選んでください。例示した技能や距離を埋めることより、プレイヤーが**「この改造で戦い方が変わった」**と観察できることを優先します。仮説を仕様へ昇格させる際は、試した結果と理由をこの文書に反映します。
