# 試作の実装判断

この試作は、[企画・実装ブリーフ](game-brief.md)の「観察 → 仮説 → 改造 → 再開 → 理解」を一巡させるための実験です。技能名、式、価格、距離は固定仕様ではありません。

## 戦場

ブラウザのCanvasに、位置とHPを持つ敵と5人の調査隊を描きます。30Hzの固定刻みで戦闘を更新し、再生速度を変えても同じ時間幅を刻んで戦闘を計算します。隊員は近い前線の敵を選び、理想距離より遠ければ近づき、近すぎれば距離を取ります。攻撃射程、理想距離、移動速度を人物ごとに持ち、軽い分離で味方同士の重なりを防ぎます。敵は上から流入し、前線で攻撃します。ゴウは近接、ナギは庇護、ヒバナは手数、ツグミは射撃と治療、ゲンゾウは術式を担当します。

HPが0になった隊員は9.5秒間戦闘不能となり、最大HPの45%で初期位置から復帰します。拠点から65m以上進んだ遠征で最初の隊員が戦闘不能になると、一度危険停止して改造の機会を作ります。全員が同時に戦闘不能になると`collapse`で自動停止し、再開を禁止して最後の拠点への撤退を案内します。v1/v2の保存データは新しい状態へ変換して読み込みます。危険判定は現在の拠点からの最高進行距離を使い、過去の最高記録が撤退後の再出発を妨げないようにしています。

引く・押すは敵の速度に作用し、重量で動き方が変わります。敵同士は重なりを解消する際に速度を交換します。「衝突損傷」を買うと、その接触に相対速度がある場合に双方へ損傷が発生します。薙ぎ払いと鎖雷は近くの敵を参照します。この関係を変える部品と、射程や攻撃間隔を調整する部品を同じ遠征資金で購入します。

直近2秒の撃破圧と被害を平滑化し、進軍速度の目標値を `5.6 × 撃破圧/秒 − 1.25 − 0.53 × 被害/秒` としています。速度も時間をかけて目標値へ追従します。撃破圧には敵ごとの重みがあります。奥へ進むほど敵のHP・流入頻度と報酬が増えます。敵が滞留すると前線での被害が増し、後退が強くなります。距離は最後に到達した拠点より手前には進みません。

## 拠点と保存

300mごとに中継拠点へ到達し、体力が回復して戦闘は停止します。その時点の所持金、購入履歴、総獲得額を拠点の状態として保存します。拠点では購入分を全額払い戻して自由に組み直せます。区間中の購入は撤回できません。撤退すると拠点を出てから得た資金と購入を巻き戻し、拠点で確定した構成に戻ります。

画面外へ移ると自動停止し、進行状態をブラウザのlocalStorageに保存します。戻ったときは停止状態から再開します。拠点から十分進んだあとに拠点近くまで押し戻されるか、隊員の合計HPが19%未満になると、危険域として自動停止します。

## 次に確かめたいこと

- 滞留、被害、撃破圧から次に買いたい部品が自然に決まるか。
- 鉤引きと薙ぎ払い、衝撃打と衝突損傷、鎖雷と敵の密集に、それぞれ違う手応えがあるか。
- 初期構成では届かない拠点に、複数の改造経路で到達できるか。現在は薙ぎ払いを買う経路を自動試験で確認しています。
- 300mの区間と購入価格が観察と再開を促す長さか。資金待ちや4×で飛ばしたい時間が多い場合は流入と収入を見直します。
- 拠点での全再配分と区間中の購入確定が、実験しやすさと選択の重みを両立するか。

スキル供給のランダム化、研究資源、物語の進行、音、長期の敵構成は、この試作を遊んでから決めます。
